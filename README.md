# Yandex.Tracker_changelogins

## Описание

Набор скриптов является **примером** переназначения пользователей Яндекс Трекер в таких сущностях как: проекты, портфели, цели, очереди, компоненты, задачи. Логика разбита на скрипты, описание которых находится ниже.

## Подготовка окружения

Для запуска скрипта необходимо:

- Получить ID Cloud Organization, которая привязана к Трекеру (bp******************) или ID организации Яндекс 360. Это необходимо для работы с API Трекера. Более подробно описано тут: https://yandex.ru/support/tracker/ru/concepts/access
- Выпустить токен сервисного приложения с правами tracker: read, tracker: write. Как получить токен (необходимо делать с учетной записи @yandex.ru администратора организации): https://yandex.ru/support/tracker/ru/concepts/access#about_OAuth.
- Заполнить файл sample.env полученными данными. Для дальнейшей работы файл необходимо переименовать в .env
- Подготовить виртуальное окружение: `python3 -m venv <название_виртуального_окружения>`. Подробнее про виртуальное окружение: https://docs.python.org/3/library/venv.html
- Установить зависимости, указанные в requirements.txt: `pip install -r requirements.txt`

## Перечень скриптов и описание работы

### mapping_users.py
Сценарий разделен на две части:
- Скрипт делает запрос списка пользователей организации с помощью метода. Полученный пул пользователей обрабатывается и сортируется на два списка:
  - `cloud_users` - пользователи, которые состоят **только** в организации Cloud Organization;
  - `directory_users` - пользователи, которые состоят **только** в организации Yandex 360;
- В списки не попадут пользователи с учетными записями @yandex.ru, которые состоят в обеих организациях.
- В списках будут только пользователи с **федеративными** аккаунтами, которые "задвоились" в Трекере.
- Далее скрипт ищет совпадения в двух списках по полю `email`. Если в списках `cloud_users` и `directory_users` найдены совпадения по значению ключа `email`, то в файле `to.txt` будет произведена запись: `<Cloud_user_ID> <Yandex360_user_ID> #`. Если необходимо поменять местами ID - нужно закомментировать строку 64 и раскомментировать строку 63 в `mapping_users.py`
- После успешного завершения скрипта в директории появится файл `to.txt`

### change_logins.py

Скрипт выполняет замену пользователей в полях "Автор", "Исполнитель", "Наблюдатели" задач Трекера. Данные по замене берутся из файла `to.txt`.


### add_entities_permissions.py
По-умолчанию в файле .env установлено значение `DRY_RUN=True`, которое влияет на запуск этого скрипта. В dry run не будет происходить обращение к API Трекера на запись;
Скрипт работает по следубщему сценарию:
- Поиск всех проектов, портфелей, целей;
- Чтение настроек доступов к сущностям;
- Чтение файла `to.txt`. Файл должен содержать список пользователей в формате `<UID старого пользователя> <UID нового пользователя>`. Пример такой записи расположен в `example_to.txt`
- Копирование прав доступа к сущностям от `<UID старого пользователя>` к `<UID нового пользователя>`


### change_components_permissions.py
Скрипт переназначает права пользователей в компонентах. По-умолчанию предыдуший пользователь не удаляется из доступов - происходит копирование прав для нового пользователя. Данные скрипт читает из файла `to.txt`. Файл должен содержать список пользователей в формате `<UID старого пользователя> <UID нового пользователя>`. Пример такой записи расположен в `example_to.txt`
Для запуска скрипта с удалением предыдущего пользователя из настроек доступа компоненты необходимо применить флаг `--remove-old-user`:
```commandline
python change_components_permissions.py --remove-old-user
```

### get_users.py
Вспомогательный скрипт, который выполняет выгрузку всех пользователей Трекера (в том числе с флагом `disabled=True`). Выгрузка сохраняется в файл `users_info.txt`. Результаты выгрузки можно использовать для дальнейшего формирования маппинга.

### changelogins_bulk.py

Скрипт работает через массовые операции редактирования. Редактирование осуществляется в одной очереди, которая указывается в `.env` файле в переменной `QUEUE`.
Замена происходит по файлу `to.txt` в полях "Автор", "Исполнитель", "Наблюдатели".
Находится в тестировании.

### change_permissions.py

Скрипт переназначает права пользователям. Находится в тестировании.


### Логирование
Вся информация о запусках сохраняется в `data.log`. Все скрипты пишут логи в едином формате в т.ч. при запуске dry run.
